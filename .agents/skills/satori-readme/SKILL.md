# satori 多语言 README 维护

## 文件结构

- `README.md` — 英文（GitHub 默认展示页）
- `README_ZH.md` — 简体中文
- `README_JA.md` — 日文

三个文件互相链接（头部 `<p>` 里的语言切换），**必须同步维护**。

## 硬规则（违反即返工）

1. **每语只写自己的语言**——英文文件里**不允许**出现中文/日文原文（包括日文汉字如「悟り」、中文标点、中文句子）。同理中文文件只写中文、日文文件只写日文。
2. **"satori 名字由来"的处理**：名字来源于日语「悟り」，但**解释用各语自己写**：
   - EN：`Satori comes from the Japanese word 悟り (satori, "enlightenment").` —— 这里「悟り」是作为"被引用的外来词"出现在英文句子里的，可以保留，因为它是专名转写的一部分；但**正文描述性句子**绝不能用日文。
   - ZH：写「来自日语『悟り』——理解、看清事物本质的瞬间」，可带日文原词作引用。
   - JA：写「日本語の『悟り』——理解し、物事の本質を見通す瞬間——に由来します」。
   - 判断标准：日文词只出现在"引用/转写"位置，不出现为句子主体。
3. **内容完全对齐**：三语段落一一对应（标题、副标题、正文每段、列表项、命令块、页脚）。改一处必须改三处。
4. **语气统一**：产品介绍要朴素、大白话、不夸张。禁止"老师""AI 给你讲"这类宣传腔；用平静陈述句。
5. **保持头部排版**：居中 `<div align="center">` + logo + `<h1>` + 副标题 + 语言切换链接，不要改动结构。

## 工作流

1. **先定中文版**（产品意图的源头），再译 EN / JA。
2. 改任何一版后，**逐段对照其余两版**，确认段落一一对应。
3. 自查：`grep` 三语文件里有没有混入其他语言的字符（中文文件搜英文长句、英文文件搜中文/日文字符、日文文件搜中文）。
4. 提交信息标注 `docs:`，一次提交三语。

## 反例（不要做）

- 只在 `README.md` 加内容、不动 `README_ZH.md` / `README_JA.md` → 三语失同步。
- 英文文件里直接贴中文句子或日文汉字作正文。
- 加"开始使用/文档链接/开发细节"等非产品内容（README 是产品介绍，不是开发文档）。

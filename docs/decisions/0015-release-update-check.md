# 0015 · 版本检查与手动更新

日期：2026-08-26 · 状态：已由 ADR 0019 取代

本记录保留 3.4.3 及更早版本的历史边界。3.4.4 起的签名应用内更新、发布清单和 bootstrap 迁移规则见 ADR 0019。

## 背景

Satori 的发布渠道是 GitHub Releases，当前产物是签名后的 macOS App ZIP。发布流程尚未生成 Tauri Updater 所需的独立签名、更新清单和可原位安装的更新包，也尚未完成 Apple 公证。此时提供“应用内安装”会制造无法兑现的承诺，并放大 Gatekeeper、签名身份和 Keychain 连续性风险。

## 决策

1. 应用启动后延迟检查一次 GitHub 的最新正式 Release，不轮询。设置页同时保留显式的“检查更新”按钮；自动检查失败保持安静，手动检查失败明确显示为可重试错误，不能冒充“已是最新版”。
2. Rust 只请求固定的 `https://api.github.com/repos/yuxino/satori/releases/latest`，当前版本来自运行中 App 的 package info，并使用 SemVer 比较。非法版本、预发布版本和较旧版本都不能触发更新提示。
3. 更新检查不读取或发送 PDF、学习历史、AI 档案、端点或 Keychain 凭据。请求只包含公开 API 所需的 Accept 标头和带当前版本的 User-Agent，并设置有限超时。
4. 只有发现新版时，首页的设置按钮才显示一个克制的状态点；设置标题栏显示当前版本、检查状态和前往下载页的按钮。更新检查与保存、测试 AI 连接等操作彼此独立。
5. 下载入口通过 Tauri opener 打开固定的 `https://github.com/yuxino/satori/releases/latest`。Capability 只允许这一个 URL，不信任 GitHub 响应中的任意外链，也不授予通用文件或网页打开权限。
6. 当前只引导用户在浏览器下载并手动替换 App。只有发布流程能稳定生成并托管经过独立更新签名的产物、清单和公证构建后，才考虑应用内下载与安装。

## 影响

- 用户能及时看到新版本，同时现有发布物可以真实支持按钮承诺的行为。
- 每次启动会产生一次不含用户内容的 GitHub API 请求；断网、限流或 GitHub 故障不影响阅读与 AI 使用。
- 自动更新仍是后续独立的发布工程任务，不能仅通过替换前端按钮文案启用。

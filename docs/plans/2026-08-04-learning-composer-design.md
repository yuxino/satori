# Satori 学习输入区交互设计

Satori 的提问区应该像阅读动作的自然延伸，而不是一张等待点击的表单。输入框保持多行，但键盘规则改为 Enter 发送、Shift+Enter 换行；旁边提供明确的图片按钮、联网开关和发送按钮。快捷问题点击后直接发起请求，不再只把文字塞进输入框。发送后，问题以一张紧凑的“我的问题”卡片留在上下文中，输入框清空，避免用户忘记刚才问了什么。生成期间，发送按钮变为停止按钮，回答卡立即出现并显示当前阶段，收到第一个文本片段后在同一张卡中持续增长。

图片是本次问题的临时上下文，不进入资料库，也不自动持久化。用户可一次选择多张常见图片，Satori 在本机压缩为最长边 1600 像素的 JPEG，最多保留四张，并在输入区显示可移除缩略图。请求仍始终附带当前 PDF 页：文字页发送原文，扫描页发送页面图像；用户图片随后按选择顺序加入同一个 Responses API 输入数组。只有点击发送后，这些内容才会离开本机。

核心层继续保留非流式 `explain` 以兼容现有调用，同时增加 `streamExplain`。流式请求设置 `stream: true`，传输层按 SSE 的 `data:` 行输出 JSON 事件；`response.output_text.delta` 立即合并到回答，`response.completed` 提供完整正文和网页引用用于最终校验。请求错误会落在现有回答卡中；取消任务会关闭底层字节流并保留已经生成的文字。测试覆盖请求中的流式标志、PDF 上下文、附加图片数量、增量拼接、完成事件与引用解析。

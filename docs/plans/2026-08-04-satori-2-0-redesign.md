# Satori 2.0 重设计提案：从「PDF + 聊天」到「共读工作台」

日期：2026-08-04 · 状态：提案（待评审）
来源：4 个子代理并行审查（学习科学 / 代码架构 / AI 管线 / UX 路径）+ 主线程构建验证。

---

## 1. 诊断：为什么现在「不好用」

### 症状（用户实际感受）

| 症状 | 具体表现 |
|---|---|
| 像 2022 年的 AI 应用 | 问答是「聊天列表 + 气泡」，AI 活在侧边面板里，和正在读的页面没有强关联 |
| 界面不自适应 | 三栏固定布局，最小窗口下 PDF 与面板互相挤压裁切 |
| 学习上「没帮助」 | 复习自测整个藏在死代码里，用户根本进不去；进度只算翻页，不代表理解 |
| 交互断裂 | 回答完成时翻页就「消失」；划选文字没有任何反应；回答跳回原文只能到页顶 |

### 根因（三层）

1. **结构问题**：产品被组织成「PDF 阅读器 + 侧边聊天窗」，AI 是附属品，而不是学习流程的一部分。所有围绕「页面」的交互（划选、锚定、回跳）都缺失或断裂。
2. **机制被藏起来**：复习自测（间隔重复）、学习目录（章节大纲）、游戏化（徽章）的**后端全部已实现**，但 UI 从未接入——`LearningInspector.swift` 的复习视图是死代码，`LearningDirectoryItem` 无任何渲染引用。投入最大的机制用户看不到。
3. **工程地基脆弱**：持久化无版本、损坏即静默重置覆盖；保存是 fire-and-forget 快照全量写，存在丢更新竞态；扫描页复习出题不带图片（对扫描版教材完全失效）；CodeRunner 超时兜底失效（SIGTERM 被忽略则永久挂死）。

---

## 2. 产品定义：Satori 是什么

> **Satori 是一个「以理解为中心的共读工作台」：PDF 是画布，AI 是共读伙伴，记忆系统是复利。**

三个核心循环，UI 必须让它们可见：

1. **阅读循环**（当下）：翻页 → 划选 → 提问/解释 → 回答锚定回页面
2. **巩固循环**（次日及以后）：章节读完自动出题 → 到期提醒 → 自测 → 评分 → 回原文纠错
3. **掌控循环**（全局）：掌握度地图（按章节）→ 连续学习 → 徽章，而不是「翻了多少页」

明确**不是**什么：不是通用 AI 聊天、不是强迫记笔记的笔记应用、不是靠翻页刷进度的游戏。判断任何功能去留的标准只有一条：**它是否让「理解」更快发生或更持久**。

---

## 3. 设计原则

1. **页面是主场**：一切 AI 交互围绕当前页与选中内容组织，AI 的回答必须能锚定回原文（页码 + 段内位置）。
2. **学习回路可见**：该复习了、答完了、掌握了——状态变化要在用户视线内发生，禁止「完成后消失」。
3. **自适应优先**：任意窗口尺寸下布局优雅。三档响应：全宽阅读 / 阅读+面板 / 紧凑浮层。
4. **手势现代化**：划选即问、键盘优先（⌘1-4 切换模式、⌘[ / ⌘] 翻页）、来源卡片可点击跳转。
5. **数字诚实**：进度 = 阅读覆盖 × 复习掌握，杜绝「翻页即学会」的指标错位。

## 4. UI 与交互重设计

### 4.1 自适应布局（三档响应）

- **窗口 ≥ 1240**：左目录栏（可折叠至 48pt 图标条）+ PDF 画布 + 学习面板（默认宽 380，可拖）。
- **窗口 960–1240**：目录栏自动收成图标条；学习面板变为可拖浮层（⌘I 呼出），不挤压 PDF。
- **窗口 < 960**：单栏阅读器 + 顶部工具条；学习面板全屏浮层。
- 全屏模式：PDF 居中最大化，面板悬浮于右侧，阅读中不打断。

### 4.2 告别「2022 聊天」：页面锚定问答卡

- 回答不再是一串聊天气泡，而是**结构化回答卡**：结论 → 证据（引用原文片段，可点击高亮）→ 推理/外部补充（分级标注）。
- 每张回答卡头部显示「依据第 N 页 · 页内位置」，卡片可折叠、可跳回原文（定位到段落，不是页顶）。
- Composer 是**上下文感知**的：显示「基于第 N 页」锚点标签、附图缩略图、联网开关；划选文字后自动变成「基于选中段落」。
- 流式回答期间显示「正在整理来源…」占位；回答完成时若用户已翻页，在面板顶部显示「回答已存入第 N 页笔记」提示卡 + 跳转按钮（修复回答消失问题）。
- 流式渲染节流 + 稳定块 ID，长回答不卡顿不跳滚动。

### 4.3 划选即问（恢复并重做）

- PDF 中划选文字 → 浮动工具条：「问 AI」「运行」「复制」。
- 提问自动携带选中段落作为锚点（后端 `ContextScope.selection` 已存在，只需接线）。
- 这是阅读中最自然的提问手势，也是精细加工（elaborative interrogation）的最佳触发点。

### 4.4 学习面板重构

- 顶部统一分段控件：**问 / 复习 / 笔记 / 运行**（⌘1-4），模式互斥、状态不残留。
- 「该复习了 N 题」金色横幅挂在问空间顶部，点击直达复习。
- 新增**目录视图**：渲染 `LearningDirectoryItem`（章节 → 页码跳转 → 完成勾选），这是「学习路径感」最缺的一块。
- 复习卡片：题目 + 「显示答案」+ 生疏/还行/记住了 + **回看原文**按钮；评分后计入连续学习与徽章。
- 笔记视图区分「确实没有」与「读取失败 + 重试」。

### 4.5 掌握度与动机系统

- 进度口径统一为 **阅读覆盖（60%）× 复习掌握（40%）**，侧栏课程行与徽章用同一算法（当前两套算法互相矛盾）。
- 徽章墙：点击 StreakCard 展开，显示已解锁徽章 + 「下一徽章还需 X」进度条。
- 复习行为计入 streak（当前只做复习会断连续学习，游戏化在惩罚最该鼓励的行为）。
- 侧栏可「新建课程」+ 右键重命名/删除（当前学习路径是死胡同）。

### 4.6 视觉规范

- 延续 Satori 家族语言：暖象牙纸面 + 单色动漫线稿 + 淡紫点缀 + 金色「火花」强调。
- 统一主题 token：SwiftUI 与 AppKit 共用一份色值定义，修正注释与设计文档漂移（Radius 等以文档为准）。
- 阅读区衬线、界面无衬线（与设计意图一致）。

## 5. 学习效果机制（学习科学落地）

| 机制 | 现状 | 目标 | 依据 |
|---|---|---|---|
| 主动回忆 | 复习自测存在但 UI 不可达 | 章节读完自动出题；复习入口显性化 | Roediger & Karpicke 2006 |
| 间隔重复 | 调度按总次数 2^(n-1)，与单题记忆强度脱节 | SM-2 风格：连续 good 次数驱动间隔，hard 后重置 | Cepeda et al. 2006 |
| 精细加工 | 只能锚定整页，划选提问被删 | 划选即问，答案带页内定位 | Pressley et al. 1987 |
| 纠错反馈 | 只有三档自评，无对照 | 评完显示原文片段 + 「回看第 N 页」 | Metcalfe 2017 |
| 交错练习 | 每页独立出题 | 支持「最近 N 页 / 本章」范围批量出题 | Rohrer 2012 |
| 动机闭环 | 只计翻页 | 掌握型进度 + 徽章 + 复习计入连续学习 | Ryan & Deci SDT |

## 6. 工程地基（不修会埋雷）

1. **持久化自愈**：JSON 解码失败 → 备份坏文件（`.corrupt-<ts>`）再提示，绝不静默重置覆盖；四个 store 引入 schema 版本 + 迁移函数。
2. **保存串行化**：视图层串行化保存任务 + 阅读位置去抖（0.5–1s），消除丢更新竞态。
3. **主线程卸载**：PDF 提取/扫描页缩略图移入后台任务，提问不再冻结 UI。
4. **CodeRunner 安全**：SIGTERM 后 1–2s 升级 SIGKILL；输出边读边限流，防止内存撑爆。
5. **AI 证据完整性**：扫描页复习出题必须带页面图像；模型 × 能力矩阵（文本/图像/搜索）落地并在设置页标注；追问上下文带页码与附件摘要；SSE 识别 `incomplete`/`failed` 嵌套错误。

## 7. 实施路线图

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **P0 地基**（2-3 天） | 持久化自愈 + schema 版本；保存串行化；后台提取；CodeRunner 安全；扫描页复习带图 | 损坏文件不丢数据；快速翻页不丢位置；提问不冻结；代码运行永不挂死 |
| **P1 体验**（2-3 天） | 复习 UI 接入 + 到期横幅；回答不随翻页消失；自适应三档布局；划选即问；目录视图 | 复习可发现可完成；小窗口不挤压；划选可提问 |
| **P2 学习深化**（2-3 天） | SM-2 调度；章节批量出题；纠错回原文；掌握度复合进度；徽章墙 | 复习质量可感知；进度不再「刷翻页」 |
| **P3 打磨** | 快捷键；设置页连接测试；键盘可达性；视觉 token 统一 | 全程键盘可操作；主题一致 |

## 8. 明确不做（本期）

- 不做移动端/浏览器端
- 不做强制笔记流程
- 不做社交/排行榜
- 不做云同步（保持本地优先；云端仅按需调用 Qwen）
- 不做「翻页进度」式游戏化（改为掌握度）

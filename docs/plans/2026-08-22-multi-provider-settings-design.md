# Satori 多 AI 服务配置与设置页设计

日期：2026-08-22 · 状态：已定稿（按用户“像正常开源软件一样支持多配置”的委托推进）

## 1. 结论

Satori 从“一个百炼 Key + 一个 Qwen 模型”升级为“多个 AI 连接配置”。首批提供三个入口：

- 阿里云百炼：内置北京 OpenAI 兼容地址，保留现有 Qwen 默认体验。
- OpenAI：内置官方 API 地址，默认使用支持图片输入的平衡模型。
- OpenAI 兼容：用户填写 API 根地址、模型 ID，并可选择该连接是否需要 API Key；覆盖 OpenRouter、Ollama 等兼容服务。

用户可以保存多个命名连接、测试连接、切换当前连接和删除连接。书库、问答历史与阅读位置继续保持 provider-independent。

## 2. 方案比较

### 方案 A：每个厂商做原生适配器

直接支持百炼、OpenAI、Anthropic、Gemini 等原生协议，覆盖最广，但图片消息、流式事件、结构化输出与错误格式均不同。第一版会把“多配置”变成一轮大型后端重写，测试面过大。

### 方案 B：多配置档案 + OpenAI 兼容协议（采用）

所有连接共享 Chat Completions 视觉输入协议，内置厂商只提供安全默认值和字段策略。它能覆盖当前百炼、OpenAI 和大量本地/代理服务，同时保留未来 `protocol` 分派点。投入与收益最平衡。

### 方案 C：只增加一个自定义 Host

改动最小，但仍然只有一套配置，不能并存多个 Key、模型或本地/云端连接，也无法可靠切换和回退，不满足本次目标。

## 3. 数据与迁移

`Store.settings` 改为：

- `active_profile_id`：当前连接 ID。
- `profiles`：非敏感连接档案，包含稳定 ID、名称、类型、API 根地址、模型 ID、是否需要 Key。
- 仅反序列化的旧 `model_id`：用于一次迁移，后续不再写回。

旧 `settings.model_id` 自动写入默认百炼档案，默认档案 ID 固定为 `model-studio-default`。已有 `com.yuxino.satori.qwen.v3 / qwen-api-key` 在首次读取该档案凭据时复制到新的 profile Keychain 条目；旧条目不主动删除，避免不可恢复的凭据损失。

API Key 不进入 JSON、日志、截图、环境变量或前端长期状态。Rust 根据 profile ID 从 macOS Keychain 读取，前端只拿到“是否已保存”的布尔状态。旧明文 `dev-api-key` 入口与读取兜底移除。

## 4. 请求层

Rust 统一验证配置、拼接 `/chat/completions`、注入可选 Bearer 鉴权、发送页面图片并解析 SSE。所有远程请求带 `store: false`；不出机的 localhost/loopback 自定义服务可以省略该扩展字段。OpenAI 使用 `max_completion_tokens`，百炼和自定义兼容服务使用兼容面更广的 `max_tokens`。

三条现有能力——页面讲解、扫描目录提取、章节页定位——都接收同一 `AIProfile`，不再传明文 Key 或单独模型参数。错误信息使用连接名称，不再硬编码“百炼”。流式事件改为 `ai://chunk`。

“测试连接”发送一个极小文本请求，不上传书页，用于验证地址、鉴权和模型 ID。真正的图片能力仍在首次读页时由服务端确认；设置页明确提示所选模型必须支持图片输入。

## 5. 设置页 UX

继续使用单窗口 sheet，改成约 780×560 的 master-detail 布局：

- 左栏列出连接名称、服务商、模型与状态；底部“添加连接”。
- 右栏编辑名称、服务类型、API 地址、模型和 API Key。
- 预设地址只读，自定义地址可编辑；模型可输入，并为百炼/OpenAI 提供建议列表。
- 已保存 Key 只显示“已安全保存”，输入框只用于替换；可单独移除。
- 底部区分“设为当前”“测试连接”“保存更改”，保存成功不自动关窗。
- 删除连接需要确认，说明只删除本地连接和钥匙串凭据，不删除学习记录。

对话具备 `role="dialog"`、焦点恢复、Esc 关闭、遮罩点击关闭、初始焦点、状态 `aria-live`，并防止重复打开。全局补齐 `:focus-visible`、高对比语义色和 `prefers-reduced-motion`。

## 6. 错误与边界

- 没有可用连接：提问时打开设置并提示先完成 AI 连接。
- 必填项缺失或 URL 不是 HTTP(S)：就地显示错误，不写入 Store/Keychain。
- Store 保存失败：不宣称成功；Key 替换与配置保存分阶段报告。
- 测试失败：保留表单与已保存配置，显示可行动错误，不自动关闭。
- 删除当前连接：若还有其他连接，自动切到第一项；最后一个连接不可删除，只能编辑或移除 Key。
- 自定义无 Key 连接：允许本地服务正常工作。

## 7. 验收

1. 旧安装启动后仍显示原 Qwen 模型，旧 Key 自动可用。
2. 可新增 OpenAI 或自定义兼容连接，分别保存密钥并在重启后保留。
3. 切换当前连接后，页面讲解、目录提取和章节定位都使用新连接。
4. JSON 与前端 DOM 中不出现已保存 Key；设置页不再提供明文开发 Key。
5. 键盘可完整打开、编辑、测试、保存和关闭设置；明暗模式布局无明显问题。

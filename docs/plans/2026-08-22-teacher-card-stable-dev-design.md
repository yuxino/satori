# 紧凑问答卡片与稳定开发壳设计

日期：2026-08-22 · 状态：已确认

## 问题

1. 问答卡片沿用书页的衬线大正文，字号和行距在 380px 宽的浮层里显得像放大的文章，遮挡书页且难以快速扫读。
2. 本机只有无 Team ID 的本地签名。安全日志显示同一 Satori 进程只请求一次 Keychain 授权，但当前开发脚本把每次前端构建都嵌进原生二进制，导致 CDHash 随 CSS/TypeScript 改动变化；开发者每次重建后首次提问都会再次授权。

## 决定

- 问答卡片采用“页边批注”而非“小号文章”：回答使用 14px 无衬线正文和 1.65 行高，卡片略宽、最大高度降低；问题、操作按钮和输入区进一步降级，书页仍是视觉主角。
- 增加仅在 `dev-live` Cargo feature 下启用的 `tauri://` 开发资源处理器。它只读取仓库构建产物 `dist/`，拒绝绝对路径、父目录和百分号编码的路径穿越，并为响应禁用缓存。
- `npm run app` 仍先构建前端，但只在 Rust、Cargo、Tauri 配置、图标、启动脚本或签名身份变化时重建并签名原生 `.app`。仅修改前端时复用同一签名壳，由它在启动时读取新的 `dist/`，因此 CDHash 不变。
- 发布构建不启用 `dev-live`，继续使用 Tauri 内嵌资源；API Key 仍只存 macOS Keychain。原生代码变化后，本地自签环境仍可能在首次主动提问时授权一次。

## 验收

- 卡片正文不再与 PDF 正文争夺层级，完整回答占用更少垂直空间，窄窗口仍可滚动。
- 两次仅改前端的 `npm run app` 构建后，`.app` CDHash 相同；第二次启动的首次主动 AI 使用不产生新的 XARA mismatch。
- 路径解析单测覆盖根资源、普通静态资源、`..` 与 `%2e%2e`。
- `npm run build`、Rust tests、Clippy、脚本语法检查通过。

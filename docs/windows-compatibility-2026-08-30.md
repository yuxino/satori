# Windows 兼容性问题记录 · 2026-08-30

## 范围

本轮只处理 Satori 自身的 Windows 兼容性，不再诊断虚拟机共享目录的复制故障。Host 负责代码、自动测试、Windows x64/ARM64 CI 和 unsigned current-user NSIS；唯一 UTM 中的安装、拖放、输入和截图由用户逐步完成。不得发布 GitHub Release，也不得在日志、截图或对话中记录 API Key 明文。

## 修复前证据

- 基线提交：`9274a1b51d9311f0cba965524822c303a5d3af9c`。该提交的旧 x64 包不得再次安装。
- PDF.js 会用一个 `Promise.all` 一次读取整本 PDF 的页面尺寸。大书会同时创建大量解析任务，并保留过多邻页画布；界面只有笼统等待提示，没有阶段、百分比、取消或停滞恢复。
- PDF 打开过程中没有持久化事务标记。异常退出后，最近文件状态不能解释上次为何中断，也没有书架级重试入口。
- Windows 本地 Store 和凭据作用域标记都通过 `rename(temp, target)` 覆盖已有文件；Windows 不允许该调用覆盖目标，因此第二次保存阅读状态或同一 AI 配置的 Key 会失败。
- 启动会提前读取安全凭据状态，并在已有书但没有 Key 时强制进入设置；普通阅读被 AI 配置阻断。
- 首页书架没有可见的“移除”入口；应用没有原生 PDF 拖放处理。
- 旧 Windows ICO SHA-256：`14f4d816d83e8e69030362b4b6f1a811a2fbfffa8f687d109e91f029e19c9b81`。图像角落不透明，Windows 快捷方式上会呈现白色硬方块。

## 修复后设计

### PDF 打开与恢复

- 打开前只检查文件元数据、PDF 头和最后 1 MiB；244 MB 以上的有效文件不会仅因大小被拒绝，复制未完成、非 PDF、权限失败和损坏会得到明确恢复提示。
- 打开过程依次显示“检查 PDF”“打开书（百分比和大文件大小）”“准备页面（百分比）”“渲染目标页”，全程保留取消按钮；120 秒没有加载进度会中止并销毁 PDF.js worker。
- 页面尺寸按 8 页一批读取并让出事件循环；只渲染当前页附近，离开较远视口会释放 canvas；单画布限制为 1200 万像素且长边不超过 8192 像素。
- 打开前持久化 `opening`，成功或失败后清除。若进程在中途退出，下次启动把它变成可重试的书架错误，不自动恢复该 PDF，也不让坏文件把应用永久锁死。

### 书架、拖放与 AI

- 首页每本书都有可见“移除”；确认框明确说明只删除 Satori 中的阅读位置、目录和问答，不删除磁盘原 PDF。
- Tauri 原生拖放一次接收一份 PDF，与“打开 PDF…”共用同一导入和安全打开流程；非 PDF 或多文件拖放显示原因。
- 启动、导入、阅读和书架管理不读取 Key、不要求配置 AI。只有提问、框选解释或目录识别等明确 AI 动作才检查当前服务；缺失时直接打开设置。
- AI 连接按鉴权、模型、限流、DNS、TLS、代理、拒绝连接和超时显示可行动错误；失败回答提供“重试”和“打开 AI 设置”。Key 始终只进入 macOS Keychain 或当前 Windows 用户的 Credential Manager。

### Windows 身份与图标

- `productName` 与窗口标题均为 `Satori`；current-user NSIS 的安装项、卸载项、开始菜单和桌面快捷方式由 CI 安装后检查为同名，快捷方式必须指向安装后的应用。
- 新 Windows PNG 保留透明角落并生成 16/24/32/48/64/128/256 多尺寸 ICO；安装器和卸载器均使用它。新 ICO SHA-256：`2cb763fa638fbdc7562f08f6bf8d0aa06cbbb965da80f4096f171f1f2f7f6965`。
